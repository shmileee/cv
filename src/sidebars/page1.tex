% Five rules decide what is in this column, where it sits, and in what order.
%
% 1. The vendor goes in the group header, never in a tag. "Cloud and
%    networking (AWS)" is why EKS and Lambda do not each carry an AWS, and
%    why "Transit Gateway" is not "AWS Transit Gateway" spending most of a
%    row on a word the header has already said.
%
% 2. A tag has to be defensible under questioning, which is not the same as
%    being narrated in a bullet: this column is the keyword surface a search
%    hits, the bullets are the evidence surface, and the two answer different
%    tests. Searching the roles, the case studies and the posts is how that
%    gets checked, but it only ever proves the positive: the written record
%    is where the work happened to be written up, not the boundary of the
%    work. CloudWatch, OpenTelemetry, IPAM, RDS, ElastiCache and Terragrunt
%    each return nothing from that search and stay regardless -- they are
%    hands-on tools that predate the site or never got a write-up, and the
%    question they invite has an answer. Absence from the writing is a
%    prompt to ask, not a verdict.
%
% 3. Tools small enough to learn in an afternoon stay out, however heavily
%    they were used. Nobody screens on them, so they cost a row and return
%    nothing.
%
% 4. Grouping follows what a tool is, not the one job it was put to here.
%    Kyverno is a Kubernetes admission engine that happens to serve an image
%    rewrite, so it sits with Kubernetes rather than under Security.
%
% 5. Order inside a group is a bin pack, not a logical sequence. Tag boxes
%    wrap greedily in a 192.76pt column with a 5.50pt gap, so source order
%    alone decides how full each row is. Each group is solved for the minimum
%    number of rows with item size w+5.50 and capacity 198.26pt, and the rows
%    are then emitted fullest first, so the slack collects in the group's
%    last row where a ragged edge reads as deliberate. Plain
%    first-fit-decreasing is not enough: it costs a row on Kubernetes and
%    delivery, which packs into three rows and not the four FFD finds.
%
% Widths come from the render, never from character counts, which means
% renaming one tag can silently cost a row: re-solve after any rename, and
% check that the next row's first tag still does not fit in the leftover of
% the row above it, or greedy wrapping will pull it up and undo the solve.
% Both lengths are derived -- 192.76pt is marginparwidth = 6.8cm set in
% preamble.tex, and the 806.6pt floor the column must not cross is A4 less
% the 1.25cm bottom margin -- so both move if that geometry does.
